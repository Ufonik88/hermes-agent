# Weekly Hermes-Agent Upstream Contribution Audit — 2026-08-12

## 1. PR submitted this week

**PR #84522 — fix(tools): refresh activity heartbeat while a tool call is in flight (#84491)**
https://github.com/NousResearch/hermes-agent/pull/84522

Problem: the gateway turn-inactivity watchdog (`gateway/run.py::_watch_gateway_turn_inactivity`,
default 30-min timeout) abandons a turn once `seconds_since_activity` exceeds the limit. Activity
was only stamped at tool start/completion, so a tool call that runs silently >30 min (quiet builds,
long pytest suites, large downloads) froze the clock and the watchdog reaped the turn's processes
mid-execution. Fix adds a daemon-thread heartbeat inside `_run_agent_tool_execution_middleware`
that touches `agent._touch_activity` every 30s while the tool is in flight, torn down in a
try/finally. Both sequential and concurrent paths funnel through that single middleware.

Verification:
- Clock linkage confirmed: `_touch_activity` sets `_last_activity_ts` (run_agent.py:3788) -> `get_activity_summary`
  -> `build_activity_snapshot` derives `seconds_since_activity` (session_activity.py:92), the exact field the
  watchdog reads (gateway/run.py:3055).
- 5 new tests in tests/run_agent/test_tool_activity_heartbeat.py, all pass on Python 3.12 (upstream CI python):
  `5 passed in 4.09s`.
- Independent reviewer (fresh subagent, no shared context): passed, no security/logic defects.
- Static security scan clean; `ruff check` clean.

Note: the work-repo clone (upstream main) lacks the py3.14 daemon_pool fix, so the concurrent test
fails under the local Python 3.14 venv (AttributeError on `DaemonThreadPoolExecutor._initializer`, the
subject of the closed #81569) but passes on 3.12. Upstream CI runs on 3.11/3.12, so CI is unaffected.
